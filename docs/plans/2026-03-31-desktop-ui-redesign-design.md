# 2026-03-31 Desktop UI Redesign 设计说明

## 1. 背景

当前 `desktop/` 已具备可用的 React + Tauri 单页工作台，但页面仍以自定义 CSS 和基础 HTML 结构为主，视觉层级、组件一致性、可扩展性与桌面软件质感都还有提升空间。

本次目标是在**不改业务流程与数据接口**的前提下，使用 `Tailwind CSS + shadcn/ui` 重做页面 UI，并尽量提升整体精致度、信息层次与可维护性。

由于本轮未收到进一步交互反馈，默认采用更适合 macOS 桌面工具的视觉方向：**浅色高质感玻璃拟态工作台**。

## 2. 约束与前提

- 保持单窗口、单页工作台结构
- 保持已有输入字段、进度事件与结果模型不变
- 不新增历史记录、任务模板、取消执行、多任务并发
- 前端继续通过现有 Tauri commands 工作
- 桌面端当前尚未初始化 Tailwind 和 shadcn/ui，需要先完成基础接入

## 3. 方案对比

### 方案 A：macOS 玻璃拟态工作台（推荐）

特点：

- 浅色背景 + 大面积柔和渐变
- 卡片使用半透明、模糊、细边框与层次阴影
- 左侧为配置和参数区域，右侧为结果与执行反馈区
- 强化“桌面工具”质感，而不是传统后台页面

优点：

- 最符合当前产品形态，视觉辨识度高
- 与现有页面的浅色、玻璃质感可以自然升级
- 对单页工作台的分区表达非常清晰

缺点：

- 需要更细致地控制对比度与边框，避免“太淡”

### 方案 B：深色专业控制台

特点：

- 深背景、高对比、偏工程监控面板
- 强调状态、表格、进度和日志感

优点：

- 数据展示会更强
- 长时间使用对部分用户更友好

缺点：

- 与当前产品“轻量桌面工具”气质不完全一致
- 初版容易做得过于像运维工具

### 方案 C：现代 SaaS 卡片化后台

特点：

- 明亮、规整、偏企业后台布局
- 组件统一但风格相对保守

优点：

- 实现风险最低
- 易于快速稳定交付

缺点：

- 美感上限相对较低
- 缺少“本地桌面应用”的独特感

## 4. 结论

采用**方案 A：macOS 玻璃拟态工作台**。

设计基调参考 `ui-ux-pro-max` 输出，结合当前桌面工具场景做适配：

- 风格：`Glassmorphism`
- 结构：监控/工作台式布局
- 重点：配置状态、输入动作、执行反馈、结果列表
- 要求：保留清晰对比度、不要用 emoji 作为图标、确保按钮/输入/表格均具备良好可读性

## 5. 视觉系统

### 5.1 颜色

不采用纯黑深色方案，而是在浅色桌面背景中引入偏冷灰蓝的层次：

- 页面背景：浅蓝灰渐变 + 柔和径向高光
- 主卡片：高透明白底 + 模糊 + 微弱描边
- 主文案：深灰蓝高对比文本
- 主动作：偏蓝紫高亮按钮
- 成功状态：绿色语义色
- 错误状态：红色语义色
- 提示/运行态：蓝色与中性色语义体系

### 5.2 排版

- 标题强调桌面软件感和秩序感
- 内容正文保持 14–16px 的稳定可读尺寸
- 结果表格与关键编号使用等宽字体辅助识别

### 5.3 图标与装饰

- 统一使用 `lucide-react`
- 不使用 emoji 作为功能图标
- 仅在关键标题、状态、指标位置使用图标，避免噪音

## 6. 页面结构

### 6.1 顶部 Hero

顶部不只是简单标题，而是一个具有软件感的头部区域：

- 左侧：产品标题、副标题、当前工作流说明
- 右侧：状态摘要，如“配置就绪 / 执行中 / 最近结果”

### 6.2 左侧控制面板

左侧为纵向控制区，承载：

- 配置状态卡
- 参数输入卡
- 操作按钮和输入说明

左栏宽度固定，适合形成“控制台”语义。

### 6.3 右侧结果工作区

右侧为更宽的主内容区：

- 顶部为运行状态与摘要指标
- 中部为进度反馈
- 底部为可滚动结果表格

## 7. 组件方案

使用 `shadcn/ui` 作为主要组件底座，优先采用现成组件组合，而不是继续手写样式块。

计划使用的核心组件：

- `Card`
- `Button`
- `Input`
- `Textarea`
- `Badge`
- `Alert`
- `Progress`
- `Table`
- `ScrollArea`
- `Separator`
- `Skeleton`

必要时补充：

- `Tooltip`
- `Tabs`（仅在确实需要切换视图时使用；首版默认不引入）

## 8. 数据流与交互

业务数据流不变：

1. 页面加载时获取 `runtimeStatus`
2. 用户填写表单
3. 提交后进入 `running`
4. 通过事件持续接收 `TaskProgress`
5. 任务完成后写入 `summary`
6. 若失败则展示结构化错误

UI 层调整重点：

- 表单禁用态更清晰
- 运行进度更可视化
- 增量结果在主表格中实时渲染
- 错误按分类展示，不与普通状态混淆

## 9. 可访问性与体验要求

- 输入控件保留明确 `label`
- 提供可见 focus ring
- 按钮禁用态明显但可读
- 颜色不是唯一状态标识，还要有文案/图标
- 避免横向滚动
- 结果表格区域可独立纵向滚动
- 动画控制在微交互级别，并尊重 `prefers-reduced-motion`

## 10. 实施边界

本轮只做 UI 系统升级，不做以下事项：

- 不改 Tauri command 语义
- 不改 `useTaskRunner` 的业务职责
- 不新增历史任务
- 不新增配置编辑器
- 不新增图表模块

## 11. 验证方式

完成后至少验证：

- `npx tsc --noEmit`
- `npx vite build`
- `cargo check`
- `cargo clippy --all-targets --all-features -- -D warnings`

同时人工检查：

- 1080px 下无横向滚动
- 运行中进度可见
- 成功/失败状态区分清晰
- 表格滚动与粘性表头正常
