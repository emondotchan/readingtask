# 月度任务后台执行与多任务实时刷新设计

## 目标

- 点击“执行”后不再自动打开任务详情弹窗。
- 如果任务详情弹窗当前打开，点击“执行”后立即关闭。
- 支持多个月度任务同时执行，互不覆盖状态。
- 列表中的今日进度、状态、累计完成数随执行进度实时刷新。
- 详情弹窗中的执行历史明细在任务运行时实时显示新增结果。
- 月度任务 ID 改为稳定格式：`YYMM:课程ID:managerID`。

## 方案

### 1. 任务 ID

月度任务新建时，使用当前年月和任务参数拼接稳定 ID：

- 格式：`YYMM:课程ID:managerID`
- 示例：`2604:12345:67890`

同月、同课程、同经理再次新建时，后端返回校验错误，避免静默覆盖已有任务。

### 2. 后端进度事件

为 `TaskProgress` 增加 `task_id` 字段。

- 月度任务执行时填充具体 `task_id`
- 普通单次阅读任务保留为空，避免影响现有快速执行流程

这样前端可以把进度事件路由到正确的月度任务行。

### 3. 前端运行态

月度任务页面不再只维护单一 `runState`，而是维护：

- `task_id -> runState`
- `task_id -> processedCount`
- `task_id -> requestedCount`
- `task_id -> items`
- `task_id -> summary`
- `task_id -> error`

每个任务独立更新，支持同时并发执行。

### 4. 列表刷新

列表展示由三部分数据合成：

- 数据库中的日进度快照
- 数据库中的累计成功记录数
- 当前运行中的实时增量结果

执行中任务收到进度事件后：

- 刷新该任务的今日进度
- 刷新该任务的状态
- 在累计完成数上叠加当前运行中的成功结果

任务完成或报错后，再回补一次数据库读取，保证列表与持久化数据一致。

### 5. 详情弹窗

详情弹窗打开时先读取数据库历史记录。

若对应任务正在执行，则展示：

- 数据库历史记录
- 当前运行中的实时结果

两者做去重合并后再渲染，使用户无需等待任务结束即可看到最新执行项。

## 风险与边界

- 新任务点击执行到首条进度事件之间，列表今日目标数可能短暂显示为空，随后会在进度同步后刷新为正确值。
- 本次不引入新的后台调度器，仍由前端分别发起多个执行请求；但由于状态已按 `task_id` 分离，前端显示不会串线。
